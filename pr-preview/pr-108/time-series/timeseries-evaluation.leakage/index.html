Leakage and Contamination¶

In one minute

An evaluation is only worth something if the model could not have known the answers. Drawing on more than forty papers, the page sorts the ways information about the test data reaches a model into one table and treats six routes: features known only later, dependent splits, choices fitted outside the loop, reuse of the test set, pretraining corpora that contain the benchmark, and language models that have read about the outcome.

Read first: Time Series Forecasting Evaluation · Time Series Forecasting Tasks

A forecast is made at one point in time, about a later one. An evaluation simulates that situation with historical data, where the later point has already happened and its value sits in the same table as everything else. Nothing in the data stops a model, or the person building it, from using that value. When it happens, the measured accuracy is higher than anything the model will deliver in use. This is leakage.

Kaufman, Rosset and Perlich define leakage as the introduction of information about the target that should not be legitimately available to learn from. They note that it is usually unintentional, enters through the collection and preparation of the data, and tends to be subtle and indirect1. Hewamalage, Ackermann and Bergmeir give the forecaster's version: the inadvertent use, while training a model, of data from the test set or of any data that is not available at inference time. They add that it happens more easily in forecasting than in classification or regression, and is harder to avoid2.

The problem is common. Kapoor and Narayanan found leakage errors documented in 17 scientific fields, affecting 329 papers that use machine learning3. Arp and coauthors checked 30 papers from the top security conferences against ten pitfalls and found data snooping at least partly present in 73% of them4.

One Table for All Leaks¶

The papers behind this page come from statistics, bioinformatics, ecology, economics, computer security, natural language processing and forecasting, and each field has its own vocabulary: selection bias, data snooping, look-ahead bias, adaptive overfitting, contamination. Read side by side, they describe one event. The reported number was computed on data that was not independent of something that shaped the model. They differ in what carried the information and in how it reached the model.

Features: The Knowledge Date¶

The idea. Every value in a dataset has two dates: the date it refers to and the date it became known. Only the second one matters for leakage. A model that forecasts Friday's demand on Tuesday may use whatever was known on Tuesday. Thursday's sales refer to a day before the target, and they are still off limits, because on Tuesday they did not exist.

The math. Kaufman, Rosset and Perlich call this the no-time-machine requirement: a legitimate model builds only on features with information from a time earlier than that of the target, or, when the problem demands it, a sufficient period earlier1. For forecasting, the reference point is the forecast origin. With a forecast made at time \(t\) for the target \(y_{t+h}\), and a feature whose value becomes known at time \(a\), the condition is

\[ a \le t, \]

for every feature and for every training example, each with its own \(t\).

To make this checkable, the authors propose a two-stage method. First, tag every observation with what is needed to decide whether it is legitimate for a given target, in practice the time it became known. Second, observe a learn-predict separation: for each target, only inputs that are legitimate for it become features, and only inputs that are legitimate with respect to all evaluation targets are used as training examples1.

Economists met the same problem with official statistics, which are revised for years after their first release. Croushore and Stark call the data as it existed on one date a vintage and the collection of vintages a real-time data set, built so that a forecast made at any date uses the data available at that date for all past dates15. In that vocabulary a value is indexed twice, \(y_{s \mid v}\), the value for period \(s\) as published in vintage \(v\), and a forecast made at \(t\) may use \(y_{s \mid v}\) only for \(v \le t\).

Watch out.

  • The wrong-horizon leak. Hewamalage and coauthors give the example of a one-day-ahead model that uses summary statistics of the whole current day: it can not run before midnight and is in effect a same-day model2.
  • Revised data is a leak in principle, and its size has to be measured. Croushore and Stark found that the root-mean-square errors of their forecasts were about the same with real-time and with revised data, while the forecasts themselves could differ considerably. They conclude with a warning about studies that claim a new method beats others when only the latest vintage is shown15.
  • Whether a feature is legitimate is a judgement about the problem and needs domain knowledge. Kapoor and Narayanan give no sub-categories for this kind of leakage for that reason, and ask researchers to justify the features they use3.
  • A result that is too good to be true is the classic symptom. Kaufman and coauthors report this as a long-standing rule of thumb in the data mining literature1.

The Split: Dependence between Training and Test¶

The idea. In most of machine learning the test set is a random sample of the data. For a time series this puts test points between training points. The model is then asked to fill a gap whose both ends it has seen, which is interpolation. A forecast in use has only one end. Since neighbouring values of a time series are similar, interpolation is far easier. The general statement is about dependence: a test point tells us about new data only to the extent that it is independent of what the model was trained on.

The math. Kapoor and Narayanan state the rule for models that predict a future outcome: the test set should not contain any data from a date before the training set3. With training times \(\mathcal T_{\text{train}}\) and test times \(\mathcal T_{\text{test}}\),

\[ \max \mathcal T_{\text{train}} < \min \mathcal T_{\text{test}}. \]

How much a violation matters depends on the autocorrelation. Take a stationary series with variance 1 and lag-1 autocorrelation \(\rho\), such as the AR(1) process \(x_t = \rho\, x_{t-1} + \varepsilon_t\). Predicting \(x_t\) from the previous value alone, with the best linear predictor, leaves an error variance of \(1 - \rho^2\). Predicting it from both neighbours leaves

\[ \frac{1 - \rho^2}{1 + \rho^2}. \]

Both follow from the standard formula for the best linear predictor of an AR(1) process. For \(\rho\) close to 1, seeing the next value halves the error variance, with no forecasting skill involved.

Three studies map out when a random split is harmful, and they agree once the goal of the prediction is fixed.

Study Setting Finding
Roberts and coauthors11 data with temporal, spatial, group or phylogenetic structure random cross-validation seriously underestimates the error; split in blocks, even when the residuals show no correlation
Bergmeir, Hyndman and Koo12 one-step autoregression, one stationary series ordinary K-fold cross-validation is valid as long as the model's errors are uncorrelated
Cerqueira, Torgo and Mozetič22 62 real series and three synthetic stationary ones cross-validation works for stationary series; for real ones the most accurate estimates come from out-of-sample methods that keep the time order

Roberts and coauthors care about transfer to new blocks, new places or new periods. Bergmeir and coauthors care about the next step inside one stationary process, where the rows of lagged values behave like regression data if the model is flexible enough. Real series are rarely stationary, which is where Cerqueira and coauthors land. The split strategies that respect the order of time are covered in Time Series Forecasting Evaluation.

Watch out.

  • Standard cross-validation trains on points later than the test points in all but one of its iterations, which Lones calls look-ahead bias; he adds that whether blocked variants are needed depends on whether the series is stationary14. Kapoor and Narayanan list k-fold cross-validation on temporal data among the errors found in published studies3. The result of Bergmeir and coauthors is the exception, and it covers one-step autoregression with uncorrelated errors, not multi-step targets or non-stationary series12.
  • Blocking has a cost. It can force the model to extrapolate beyond the range of the predictors it saw, which overestimates the error of interpolation; which of the two is wanted depends on the goal11.
  • Series in one collection leak into each other. If the series of a global model are not aligned in time, one series can contain the future of another, and a shock that hits all of them is already in the training set. Hewamalage and coauthors consider this likely in competition datasets whose series are not aligned2.
  • Rolling-origin evaluation moves data from the test set into the training set by design, each time the model is retrained, which makes the implementation easy to get wrong and hard to check from outside2.

Choices: Everything Fitted Belongs inside the Loop¶

The idea. A model is more than its weights. The features that were kept, the scaling constants, the hyperparameters, the architecture and the stopping point were all chosen with data. Whatever data took part in those choices has been trained on, even if no gradient ever touched it. If that data includes the test set, the test is no longer a test.

The math. Varma and Simon state the condition: cross-validation is only proven unbiased if every part of training, including feature selection, the choice of classifier and the tuning of parameters, takes place inside each loop, on the data that was not left out8. Choosing the hyperparameters that minimize the cross-validation error and then reporting that minimum breaks the condition, because the choosing is itself training. The remedy is to treat "tune, then fit" as the procedure under evaluation and to wrap it in a second loop, called nested cross-validation:

\[ \widehat{\operatorname{Err}} = \frac{1}{K} \sum_{k=1}^{K} L\left( \mathcal D_k, \; \operatorname{fit}\left( \mathcal D_{-k}, \; \hat\lambda(\mathcal D_{-k}) \right) \right), \]

where \(\mathcal D_k\) is the outer test fold, \(\mathcal D_{-k}\) the rest, and the hyperparameters \(\hat\lambda\) are tuned by an inner cross-validation that only sees \(\mathcal D_{-k}\).

The size of the effect, from three sources:

  • Varma and Simon simulated data with no difference between the classes, so that the true error is 50%. The cross-validation error of the tuned classifier was below 30% on 18.5% of the simulated datasets for one classifier and on 38% for another. Nested cross-validation gave estimates close to the true error8.
  • Cawley and Talbot showed that the bias from tuning outside the evaluation loop is often as large as the differences between learning algorithms. In their experiments, switching one of three classifiers to the biased protocol moved its average rank from about 2 to 1.23 and made it statistically superior, a difference they call entirely spurious9.
  • Kapoor and Narayanan list the usual violations: preprocessing on the whole dataset, such as imputation or oversampling before the split, feature selection on the whole dataset, and duplicates on both sides of the split3.

Feature selection shows the mechanism in a case that can be computed. Take \(p\) candidate features that are pure noise and \(n\) samples. The sample correlation \(r\) between one such feature and the target is approximately normal with mean 0 and standard deviation \(1/\sqrt{n}\). The largest \(\lvert r \rvert\) among all \(p\) grows roughly like

\[ \sqrt{\frac{2 \ln p}{n}}, \]

which for \(p = 200\) and \(n = 100\) is about 0.33. These are standard approximations for independent normal variables, meant as orders of magnitude; the widget computes the real thing.

Watch out.

  • Preprocessing counts. For time series, Hewamalage and coauthors name smoothing, decomposition and normalization applied to the whole series before the split, and features computed over the whole series, which have to be computed from training data only and recomputed as time moves on2. Lones adds data augmentation done before splitting14, and Arp and coauthors add cleaning, such as removing outliers with statistics of the complete dataset4.
  • A biased protocol does not shift every method by the same amount. Methods with more hyperparameters gain more from it, so comparisons made under such a protocol are not consistent with each other9.
  • The leak can run through the modeler. Kaufman and coauthors point out that choices of features, algorithms and settings made with knowledge of the evaluation data leak in a way an evaluator may not be able to detect, and that in time series prediction, where usually only one history exists, this form is endemic1.
  • To make the separation checkable by others, Kapoor and Narayanan propose model info sheets, in which authors argue for the separation of training and test data, the legitimacy of every feature, and the match between the test set and the claim3.

Reuse: The Test Set Wears Out¶

The idea. Suppose every single experiment is clean: the model is trained without the test set and scored on it once. Now repeat this fifty times, each time keeping the changes that raised the test score. No experiment leaked, and the sequence did, because each score that was looked at carried a little information about the test set into the next decision. A whole research community working on one benchmark for years does the same thing on a larger scale. The papers on this question fall into two groups: theory that shows how bad it can get, and audits that measure how bad it has been.

The math. Blum and Hardt model a leaderboard as a sequence of adaptively chosen classifiers \(f_1, \cdots, f_k\) and released scores \(R_1, \cdots, R_k\), and measure it by how far the best released score is from the truth20,

\[ \operatorname{lberr}(R_1, \cdots, R_k) = \max_{1 \le t \le k} \left\lvert \min_{1 \le i \le t} R_D(f_i) - R_t \right\rvert , \]

where \(R_D\) is the true loss. For a leaderboard that simply reports the holdout loss on \(n\) examples, they construct a sequence of submissions that drives this error to the order of

\[ \sqrt{\frac{k}{n}} . \]

Their remedy, the Ladder, releases a new score only when a submission improves on the best so far by more than a step \(\eta\), and repeats the previous best otherwise. Its error grows only with the logarithm of the number of submissions20. Dwork and coauthors give a related mechanism, the reusable holdout, which answers a query from the training set whenever training and holdout agree and reveals a noisy holdout value only when they do not. In their demonstration on data with random labels, an analyst who reuses a standard holdout for variable selection reports an accuracy above 63% where 50% is the truth19.

Recht and coauthors supply the accounting for what a drop on fresh data means. With the original test set \(S\) from distribution \(D\) and a new test set \(S'\) from \(D'\)10,

\[ L_S - L_{S'} = \underbrace{(L_S - L_D)}_{\text{adaptivity gap}} + \underbrace{(L_D - L_{D'})}_{\text{distribution gap}} + \underbrace{(L_{D'} - L_{S'})}_{\text{generalization gap}} . \]

Only the first term is the wear of the test set. The second is that the new data is different, and the third is sampling noise.

The audits:

Study What was compared Finding
Recht and coauthors10 image classifiers on the original and on newly built test sets accuracy drops of 3% to 15%, but the ranking of models is kept, and later models gain more on new data, which speaks against adaptive overfitting as the cause
Roelofs and coauthors21 public leaderboard against private test set in more than one hundred Kaggle competitions little evidence of substantial overfitting; the outliers have a non-random split or very small test sets
Zhang and coauthors28 language models on a public arithmetic benchmark and a newly written twin drops of up to 8% for some model families, minimal for many models at the frontier

Watch out.

  • The worst case and the typical case are different things. The theory is about what an adversary can do. The audits found that large benchmarks with random splits have held up. Neither result covers the long-horizon forecasting benchmarks, whose test sets are a few thousand overlapping windows of one series and so contain far fewer independent samples than their size suggests. None of the papers read for this page reports an audit of them.
  • Lones calls the everyday form sequential overfitting: training models in succession, each guided by the test score of the last. His remedy is the classical one, a validation set for guidance and a holdout touched once14.
  • Small test sets fail first. In the Kaggle study, the competitions with large gaps between public and private scores had private test sets as small as 100 examples21.
  • Brigato and coauthors retrained eight long-horizon forecasting models with equal tuning effort on 14 datasets and found no model that consistently beats the others. Among their recommendations are test sets that are withheld and scored by a third party29.
  • Each look at the test set is also one of the comparisons counted in Is the Difference Real?.

Pretraining: Three Meanings of Zero-Shot¶

The idea. Pretrained forecasting models are trained once on a large collection of public time series and then applied to new series without further training, which is called zero-shot forecasting. The claim "zero-shot" is a claim about the past of the model: that it has not seen what it is tested on. Public benchmarks are built from public datasets, and so are pretraining collections. When they overlap, the model is tested on data it was trained on, and nobody had to make a mistake in their own code for it to happen. Reading the model papers side by side shows that "has not seen" is used with three different meanings.

The math. Let \(\mathcal C\) be the pretraining corpus and let the benchmark consist of series \(y^{(i)}\), each split at a date \(\tau_i\) into a training part and a test part.

Level Condition Who uses it
1. No dataset overlap no part of any \(y^{(i)}\) is in \(\mathcal C\) the zero-shot benchmarks of Chronos27, Moirai25, TimesFM26, Lag-Llama30, Time-MoE31 and Sundial32
2. No test-split overlap only \(y^{(i)}_{t \le \tau_i}\) is in \(\mathcal C\) MOMENT, which pretrains on the training splits of all its datasets13; Chronos and Moirai report this case separately as in-domain or in-distribution2725
3. No temporal overlap nothing in \(\mathcal C\) is later than the start of any test period proposed by Meyer and coauthors as a global temporal barrier7

Level 2 keeps the test values out of the corpus and still lets the model learn the earlier part of the very series it will forecast. The fev-bench authors count both cases as leakage: exposure to the test split inflates accuracy directly, and training on the training split violates the zero-shot setting, since the model has already seen the series it is asked to forecast6. Sainz and coauthors drew the same line for language models two years earlier: contamination with the evaluation split invalidates the experiment, and contamination with the training split invalidates the zero-shot claim5.

Level 3 exists because of indirect leakage. Meyer and coauthors separate direct leakage, where the same samples appear in training and test data, from indirect leakage, where a training series and a test series are correlated and overlap in time. A shock that hits many series at once, such as the start of the pandemic, is then in the training data even though the test series is not7.

For the size of the bias, let a fraction \(f\) of the benchmark be affected. If the model's expected error is \(E_{\text{seen}}\) on those series and \(E_{\text{unseen}}\) on the rest, the benchmark reports

\[ E_{\text{benchmark}} = f \, E_{\text{seen}} + (1 - f) \, E_{\text{unseen}}, \]

while a new user gets \(E_{\text{unseen}}\). The bias \(f \, (E_{\text{unseen}} - E_{\text{seen}})\) differs from model to model because \(f\) depends on each model's corpus. Magar and Schwartz measured the two factors separately for a language model and called the difference between seen and unseen test items exploitation. They found that it can be zero even when the model has memorized the data: memorized is not always exploited24.

How much overlap is there, and what is done about it?

  • Meyer and coauthors traced the data of 22 published time series foundation models. Of the 401 datasets involved, 6% had never appeared in any model's pretraining or fine-tuning data, and no dataset was reserved for evaluation by everyone7.
  • The Moirai authors name the root problem: there is no standard held-out split, so it is hard to collect datasets that none of the compared models was trained on25.
  • Subtraction: TimesFM, ProbTS and Sundial drop, for each model, the datasets it was pretrained on, which leaves different models evaluated on different data263332.
  • Flagging and retraining: GIFT-Eval reports the overlap for three published models, provides a pretraining collection without overlap, and retrains one model on it. On the affected datasets the leaked version scores better in most cases34.
  • Imputation: fev-bench asks contributors to declare overlap, shows it as a column of the leaderboard, and replaces a model's results on leaked tasks with those of a reference model, so that all aggregate scores cover the same tasks6.

The target series is never in the pretraining data; the other series is, either up to the split date or through the test period. A memorizing model forecasts the target series by recalling the continuation of the most similar context in its corpus. It needs JavaScript. In short: when the other series is known through the test period and the two series share most of their variance, the forecast of the never-seen target follows the shock and its error is much lower; when they share little, there is no gain.

Watch out.

  • Overlap can not be detected from the outside today. The fev-bench authors point out that automatic detection amounts to membership inference over pretraining corpora, an open problem for language models and harder for numerical data, and fall back on self-reporting6. Meyer and coauthors argue the opposite way: since disclosure can not be verified, the benchmark and not the model has to guarantee the separation7.
  • The same data at another sampling frequency: fev-bench does not count it as leakage6, Meyer and coauthors say frequency variants of one process should be treated as dependent7.
  • A leak does not always raise the score. In GIFT-Eval the leaked model is better in most cases, not all34, and in the experiment of Meyer and coauthors the model with overlapping data was better in eight of ten runs7.
  • The designs that rule leakage out have costs. Withheld test data needs rate-limited submissions and gives no per-series errors, and prospective evaluation, where forecasts are submitted before the truth exists, means waiting for months6.
  • Report in-domain and zero-shot results separately, as the Chronos and Moirai papers do, and say for each compared model which level of the table above it meets2725.

Language Models: A Feature with an Unknown Knowledge Date¶

The idea. When a large language model is used to forecast, or to produce features for a forecaster, the first route of this page returns in a new form. The model is a feature whose knowledge date nobody can state exactly. If its training text includes the period being backtested, it may know the outcome, and a backtest then measures recall. Economists call this look-ahead bias. Sarkar and Vafa define it for language models as the case where the pretraining data contains information about the future, which then leaks into an analysis that should only use information from the past16.

The math. Lopez-Lira, Tang and Zhu state the problem as one of identification. When the model has seen the realized values, any observed forecast accuracy is consistent with skill and with memorization, so the forecasting ability on that period is not identified by the backtest at all17. The remedy is the level-3 condition of the previous section, applied to the model: the test period has to lie after everything the model was trained on.

Because the corpus is usually not available, a family of tests tries to detect exposure from the model's behaviour.

Test Signal of exposure Source
Before and after the cutoff performance is better on items released before the training cutoff than after Roberts and coauthors35, Li and Flanigan36
Unpredictable events the model predicts something that could not be known from the stated information Sarkar and Vafa16
Completion given the first part of a test item, the model reproduces the rest Golchin and Surdeanu37
Slot guessing the model fills in a masked wrong answer option of a test question Deng and coauthors38
Canonical order the model finds the published order of a dataset more likely than shuffled orders Oren and coauthors39
Low-probability tokens the least likely tokens of a text are less unlikely than for unseen text Shi and coauthors40
Extraction training sequences can be drawn out of the model verbatim Carlini and coauthors23

The statistic of Shi and coauthors shows how such a test is built. For a text \(x\) with tokens \(x_1, \cdots, x_N\), take the set \(\text{Min-K\%}(x)\) of the \(k\)% of tokens to which the model assigns the lowest probability, \(E\) tokens in all, and average their log-likelihood40,

\[ \text{Min-K\% Prob}(x) = \frac{1}{E} \sum_{x_i \in \text{Min-K\%}(x)} \log p(x_i \mid x_1, \cdots, x_{i-1}) . \]

A text the model has not seen tends to contain a few tokens it finds very unlikely; a seen text less so.

Of these tests, the first two carry over to time series without change, because they need only dates. The canonical-order test relies on the examples being exchangeable, which the observations of a time series are not.

The picture. The widget shows the before-and-after test from the forecaster's side. Each bar is the error for one month. For the months the model has seen, the answer is partly recalled and the error is low. The backtest uses the months after the stated cutoff.

Try it. Press Play to move the true extent of the model's knowledge past its stated cutoff and watch the backtest error fall while the model's real forecasting ability stays the same.

An interactive bar chart of forecast error by month for a model with a knowledge cutoff. Months the model has seen have a low error because the answer is recalled. One slider sets the stated cutoff, after which the backtest period starts, and another sets how far the model's knowledge really extends. It needs JavaScript. In short: when the model's knowledge extends beyond the stated cutoff, part of the backtest period is recalled, and the backtest error is lower than the error the model would have on a period it has truly not seen.

Watch out.

  • A stated cutoff is not a boundary. Paleka and coauthors note that cutoff dates are published to inform users, mean different things for different developers, and are not guarantees; they show a model that reveals an event from after its stated cutoff18.
  • Asking the model to forget does not work. Instructions to ignore later information do not remove the bias16, and masking names and dates fails because the model reconstructs them from context17.
  • The tests are one-sided: a detection shows leakage, and a non-detection does not show its absence16. Evidence of memorization is a lower bound on what the model has encoded17.
  • The effect is not always large or in one direction. Glasserman and Lin found that, inside the training window, anonymizing company names improved trading signals from news sentiment, so that the model's general knowledge about a company was more of a distraction than a help41.
  • Hindsight also enters through the benchmark. Questions selected because they have resolved by now, or written after the fact from news reports, carry their answers in the selection18. Sarkar and Vafa describe the same for training text that has survived, for example about firms that still exist16.
  • Prevention is by design. Proposals include test data published in encrypted form42, benchmarks that are refreshed monthly from recent sources43, and newly written twins of public test sets28.

Not Leakage, but the Test Set Still Moves

Two findings from benchmark studies belong next to this page. Neither passes test information to the model; both change what the reported number means.

  • Many long-horizon forecasting codebases batch the test windows and discard the last incomplete batch. Which windows are scored then depends on the batch size. Qiu and coauthors show the reported error of the same models falling steadily as the batch size grows, and do not drop the last batch in their own benchmark44.
  • Shao and coauthors collected the numbers reported for the same baselines on the same datasets in several widely cited papers and found that they differ, and traced this to normalization, loss masking and the way metrics are computed. They also note that errors reported on normalized data look small45.

Where the Literature Disagrees¶

Question One position The other
Is K-fold cross-validation valid for time series? yes, for one-step autoregression with uncorrelated errors12 no in general, block the data11; out-of-sample is best for real series22
How harmful is reusing a test set? provably harmful in the worst case2019 little harm found in large audits1021
Does contamination raise scores? clearly, in before-and-after comparisons353617 not always: memorized is not always exploited24, and one audit of four models found little evidence of pervasive contamination39
Is pretraining on the training split acceptable? yes, it avoids contamination of the test split13 it invalidates a zero-shot claim65
Who has to guarantee clean data? model builders, by disclosure and cooperation426 the benchmark, because disclosure can not be verified7

The disagreements mostly dissolve once the claim is made precise: which prediction task, which notion of "unseen", worst case or typical case. That is the practical lesson of reading the papers together. A statement about leakage needs its definition next to it.

In Practice¶

Before trusting a score, including one's own:

  1. For every feature: on which date did this value become known, and is that before the forecast origin of every example it is used for?
  2. Is anything in the training data tied to the test data: later in time, the same series, or another series over the same period?
  3. Was everything that was fitted, including scaling, feature extraction and hyperparameters, fitted without the test data?
  4. How many times has this test set been used to make a decision, by you and by the papers you build on?
  5. For a pretrained model: which of the three levels of "unseen" holds for each dataset, and for each model in the comparison?
  6. For a language model: does the test period lie after everything the model was trained on?

And one symptom: a result far better than a strong baseline, or than anything published on the same data, is more often a leak than a breakthrough.
